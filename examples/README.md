# Examples

Fakes that FauxCall built on its own, from a single prompt each, while it was being validated (see
[how FauxCall was validated](../docs/validation.md)). Nobody edited their code: what you see is what
a headless Claude Code session produced with the FauxCall plugin and nothing else.

`fauxcall/` is a FauxCall workspace, exactly as `/fauxcall` creates one in your own project: one
folder per fake, sharing a uv workspace.

| Fake | Imitates | Built from | Endpoints | Recordings | Parity with the real API | Offline tests |
|---|---|---|---|---|---|---|
| [`frankfurter`](fauxcall/frankfurter/README.md) | [Frankfurter](https://frankfurter.dev), ECB exchange rates | OpenAPI document | 9 | 219 | **100%** over 142 scenarios | 427, 99% coverage |
| [`refapi`](fauxcall/refapi/README.md) | The [reference API](../reference_api/) in this repository | Swagger UI page | 21 | 877 | **100%** over 188 scenarios, real writes included | 818, 99% coverage |
| [`timeapi`](fauxcall/timeapi/README.md) | [timeapi.io](https://timeapi.io), time zones and conversions | Swagger UI page | 28 | 576 | **100%** over 192 scenarios | 1,366, 98% coverage |

Each fake's README says how to run it, what it does differently from the real service, and why.
Its `data/reports/` folder holds the parity report and a summary written when it was built.

## Run them

From this folder, with this checkout of FauxCall:

```bash
uv run --project .. fauxcall up               # start all three in the background
uv run --project .. fauxcall up frankfurter   # or just one
uv run --project .. fauxcall down             # stop them
docker compose -f fauxcall/compose.yaml up    # or in containers
```

They listen on `http://127.0.0.1:8701` (Frankfurter), `:8702` (reference API) and `:8703`
(timeapi.io). Point an agent at one of those instead of the real service. Every fake also has an
admin API under `/__fauxcall` to reset its state, control its clock, read the calls an agent made and
inject faults.

## Test them

```bash
cd fauxcall/timeapi
uv run pytest                                # everything offline: unit tests, replays, scenarios
uv run pytest tests/e2e --target=parity      # the same scenarios against the real API and the fake
```

Parity runs need the real service. Frankfurter and timeapi.io are public and need no credentials.
For the reference API, start it from the repository root (`uv run fauxcall-reference-api --port
9100`) and put its documented demo key in `fauxcall/refapi/.env`:
`FAUXCALL_REAL__HEADERS='{"X-API-Key": "demo-key"}'`.

CI runs every fake's offline suite, lint and type checks on each push
([`.github/workflows/fauxcall.yml`](../.github/workflows/fauxcall.yml), generated by `fauxcall
scaffold`), so the examples keep working as FauxCall changes.

## What changed after they were built

The fakes are snapshots: they were built with FauxCall as it was on 11 October 2026, and FauxCall
kept improving from what these runs revealed. Two consequences:

- **Their READMEs mention limits that FauxCall has since fixed.** The reference API's README says a
  429 can't be lifted by moving the fake's clock (an `advance` now lifts it), and that the fake
  accepts the test harness's key `fauxcall-test-key` (the tests now add that key for themselves, so a
  newly built fake wouldn't list it in its `fauxcall.toml`).
- **Ports were reassigned.** Each fake was built in its own workspace and got port 8701. When they
  were brought together here, `fauxcall scaffold` moved two of them to 8702 and 8703 (in their
  `fauxcall.toml`), and the port numbers in their READMEs were updated to match. That is the only
  change made to the generated files.

## About the data

The recordings are real responses from the services, captured by `fauxcall record`. Credentials are
redacted and personal data is pseudonymized before anything is written to disk; these three services
return no personal data. Frankfurter publishes the European Central Bank's reference rates, and
timeapi.io answers with computed times. The reference API is this repository's own test server.
